# LayoutX2C 1.4.0

LayoutX2C 1.4.0 extends the runtime customization path introduced in 1.2 and
1.3 with generated synthetic `AttributeSet` data for explicitly supported
custom views. It remains a compatible minor release: unsupported attributes and
runtime-only platform semantics continue to fall back conservatively.

## Highlights

- Generated custom View creation can pass namespace, attribute name, raw value,
  and statically resolved resource IDs through `SyntheticAttributeSet`.
- `ViewFactory` integrations can inspect the synthetic attributes before the
  default constructor path is used.
- Typed custom attributes declared through `@FastCustomViews` continue to be
  replayed through generated setters.
- `layoutX2C.enableSyntheticAttributeSet` allows projects to disable this
  compatibility path explicitly.
- Existing `ResourceLoader` and `ViewFactory` runtime extension hooks remain
  available with their default behavior when no custom implementation is
  registered.

## Safety Boundary

Synthetic attributes are passed to the `ViewFactory` hook. They do not emulate
Android's internal `XmlBlock.Parser`, so generated default View constructors do
not receive a synthetic parser as a substitute for platform XML inflation.
Unsupported theme, style, or constructor semantics still use fallback.

The release includes JVM coverage for parsing and code generation plus Android
instrumentation coverage for the synthetic custom-view path. It does not make a
blanket equivalence claim for every generated View or every third-party
inflater.
