# LayoutX2C 1.4.1 Candidate

LayoutX2C 1.4.1 is the next patch candidate after 1.4.0. These notes describe
the repository candidate and do not claim that the version has already been
published.

## Runtime And Build Improvements

- Application and Android library modules generate registry providers that are
  discovered through `ServiceLoader`; reflection remains as a compatibility
  fallback for older generated application registries.
- Multi-module TestKit coverage verifies that application and library providers
  are merged into the packaged application.
- The Android build baseline moves to AGP 9.3.1, with Gradle parallel tooling
  synchronization enabled where supported.
- Generation and report contracts were aligned so registry providers, fallback
  summaries, and cached outputs remain deterministic.

## Release Readiness

- One root version provider now owns all artifact and plugin dependency
  coordinates. `layoutx2c.version` and `VERSION` are accepted explicit inputs,
  and conflicting values fail configuration.
- Plugin dependency injection reads generated version metadata instead of a
  second hard-coded version constant.
- `consumerSmoke` publishes every component and the Gradle plugin marker to an
  isolated Maven repository, then consumes them from a standalone Android build
  without composite substitution or TestKit classpaths.
- `validateReleaseCandidate` rejects implicit, malformed, SNAPSHOT, or
  tag-mismatched release inputs before expensive work begins.
- `releaseCheck` combines JVM and Android tests, coverage reports, Android
  assembly, local publication metadata validation, and the standalone consumer
  smoke test without remote publication.
- Release history, migration guidance, and adoption links now use stable,
  versioned documentation paths.
